# SEO / AEO / GEO — what this site does and how to maintain it

> Context: the avianna.ai domain previously belonged to an unrelated drone-software
> company (acquired by Lucid Bots, July 2024). Search engines and LLMs inherited that
> association. Everything below exists to establish the correct entity — Avianna, an
> independent AI research lab — and to keep the site fully readable by search and
> answer engines. Set up 2026-08-15/16.

## On-site inventory

| Piece | Where | Notes |
|---|---|---|
| robots.txt | `/robots.txt` | All crawlers allowed; AI/LLM crawlers (GPTBot, ClaudeBot, PerplexityBot, …) listed explicitly. Points to sitemap. |
| llms.txt | `/llms.txt` | Entity summary for LLM crawlers: who we are, products, writing, official profiles, disambiguation line. **Update when**: a post ships, a product launches, or an official profile is created. |
| sitemap.xml | `/sitemap.xml` | Generated by `scripts/build_static.py` — do not hand-edit. |
| feed.xml | `/feed.xml` | Atom feed, generated by `scripts/build_feed.py`. Also submitted to Google as a sitemap. |
| Organization + WebSite JSON-LD | `index.html` head | The entity root. `@id: https://avianna.ai/#organization`. `sameAs` lists official profiles — **every new official profile gets added here AND to llms.txt**. |
| Person JSON-LD | `tushar.html` head | `@id: …/tushar.html#person`, referenced by every BlogPosting author field. |
| BlogPosting JSON-LD + canonical + OG | every `posts/*.html`, `lattice/part-*.html`, `lattice/gaps.html` | Generated pages get theirs from the build script; hand-authored pages carry them in-file. |
| SoftwareApplication JSON-LD | `concord/`, `lattice/`, `learn/` index pages | Product entities, publisher → the Organization `@id`. |
| FAQPage JSON-LD + definitional sections | `concord/index.html`, `lattice/index.html` | The coinage: "agent contract" and "onboarding digital labor" defined in quotable form, high in the DOM. |
| Static blog index | `blog.html` between the `POST-LIST` markers | Server-rendered so non-JS crawlers see every post link. Generated — do not hand-edit inside the markers. |
| Static post pages | `posts/<slug>.html` | Every markdown post also exists as static HTML (crawlers don't run JS). `post.html?slug=` still works and canonicalizes onto the static page. |
| 404.html | `/404.html` | Branded; disambiguates from the old drone company for legacy indexed URLs. |
| IndexNow key file | `/<key>.txt` at root | Lets deploys ping Bing/Copilot for instant recrawl (see below). |

## Publishing a post (the full ritual)

1. Drop markdown under `content/<section>/<slug>.md`, add the entry to
   `assets/js/posts.js` (see the header comment there).
2. Bump the `?v=` cache-buster on the script tags in `blog.html` and `post.html`.
3. `python3 scripts/build_feed.py`
4. `python3 scripts/build_static.py`  (needs `pip install markdown`) — regenerates the
   static post page, blog index, and sitemap.
5. Add the essay to `llms.txt` → Writing.
6. Commit, push (Pages deploys from `main`), then ping IndexNow:

   ```
   curl -s -X POST https://api.indexnow.org/indexnow \
     -H 'Content-Type: application/json; charset=utf-8' \
     -d '{"host":"avianna.ai","key":"<key from the root .txt file>","keyLocation":"https://avianna.ai/<key>.txt","urlList":["https://avianna.ai/posts/<slug>.html","https://avianna.ai/blog.html"]}'
   ```

## Search engines

- **Google Search Console**: domain property `sc-domain:avianna.ai` (DNS-verified).
  `sitemap.xml` + `feed.xml` submitted; key URLs manually requested for indexing
  2026-08-16. Scoreboard: Performance → query "avianna".
- **Bing Webmaster**: property verified, sitemap submitted. Bing feeds ChatGPT
  search and Copilot. Its **AI Performance** tab shows AI-answer citations.
- **IndexNow**: key file at the repo root; ping after every content deploy.

## Email authentication (DNS)

All three records live in GoDaddy DNS and all must stay intact for @avianna.ai
mail to be delivered (Gmail silently discards on failure):

- **SPF** (TXT @): `v=spf1 include:secureserver.net include:spf.protection.outlook.com -all`
- **DKIM**: CNAMEs `selector1._domainkey` / `selector2._domainkey` → Microsoft
  (`…NETORG19141214.w-v1.dkim.mail.microsoft`), signing enabled in M365 Defender.
- **DMARC** (TXT `_dmarc`): `v=DMARC1; p=none; rua=mailto:tushar@avianna.ai` —
  exactly one DMARC record, ever. Tighten `p=none` → `p=quarantine` after a few
  clean weeks of reports.
